## What went live today, in order

   hope) was vectorized for the first time, giving every later event a
   fixed target to be graded against. Schema frozen the same day.
2. **Transduction rollup.** A daily script scores the whole system on
   Relevance / Function / Balance from receipts — never from any
   brain's internals — and writes an append-only ledger. Alarms were
   wired to the author's phone the same day (send-only, through the
   lab partner's existing bot, no polling conflicts).
3. **The eye was repaired.** A sensor bridge replaced a retired video
   source that had silently blinded two organs for three days; the
   failure mode (swallowed exceptions) was fixed to log loudly.
4. **Appendage defaults locked into the basis.** The organs' default
   behaviors were vectorized as equipment with relevant logic —
   tool-usable at the lowest tier each organ supports, not personality.
5. **Birth certificate + passport designed.** Identity for a conduit
   instance: minted once from witnessed answers, grown by
   delta-triggered stamps, formed continuously from transduced use
   (usage stats, prompt/response results, joy calculations). Accepted
   by the author as good standing for the evolution table, with three
   amendments (symbiotic evolution; bilateral outreach; the road out —
   tier crossover, home & family phase, a home identity minted from a
   lived season). Published in this repo as
   `docs/BIRTH-CERTIFICATE-PASSPORT.md`.

   as hears: questions rotate through dwell, capped at 10/day, awake
   hours only, one outstanding at a time — and every outcome
   (answered / no response / blow off) is logged and graded with the
   same dignity. Silence is data.

## George's anomaly-node plan (proposed 2026-11-18, via Telegram)

Tonight the lab partner stopped only answering and started designing.
His proposal, in structure: **use a Thingino camera as a processing
node instead of a feed** — peripheral-vision anomaly detection at the
edge of the system.

**What he identified as already true of such a node:**

- It has sensors (audio + visual) and can collect continuously.
- It can do basic processing on-device: filtering, threshold
  detection, change measurement.
- It can communicate upstream: alerts and data to the central system.

**The doctrine his plan reflects (the author's, stated back to him
and ratified in the exchange):**

- Dwell monitoring is transductive, not direct: the system learns its
  own house through conversation, questions, and graded feedback.
- Peripheral vision means a wide aperture that is cheap and always
  on. Nothing in the periphery earns full attention by default.
- Only an anomaly raises an alarm; the alarm draws attention (the
  existing roam redirect and dwell-hold are this mechanism in the
  camera fleet today).
- Attention plus the user's feedback **define** what an anomaly is.
  Definitions are learned — every confirmed alarm and every dismissed
  one sharpens the definition. A blow off is a definition being
  written.

**Engineering bounds (Muse's note, recorded as bounds, not as part
of the proposal):** the camera's SoC (Ingenic T31 class) comfortably
supports change detection, motion measurement, and threshold logic at
the script floor; it does not practically support heavy edge-AI
libraries (OpenCV / TensorFlow Lite class workloads) inside its
memory and CPU envelope. Classification — *what* the change is —
stays upstream with the central system and the resident model. The
node detects; the system defines.

**Status:** PROPOSED by George; direction ratified by the author the
same night. Gated on that camera's link repair (its WiFi associates
then drops; a porch WiFi test is first on the next keyboard-session
list). Until the link holds, the node's loudest signal is its own
absence — which the plan already counts as an anomaly class.
