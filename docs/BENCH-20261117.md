# Divided-workload benchmarks — 2026-11-17

The question under test (Zak): does the core do multi-tier analysis and
bifurcation — splitting work across tiers by timing, delay, performance
and human expectation — on whatever hardware it is dropped on?

Method: census.py reads the box, pipes.py recognizes its pipes and
lanes them, the budget bifurcates (conversation seat pinned first, task
seats from the remainder, script floor underneath everything), and the
expectation table states what each tier may promise. Numbers below are
MEASURED unless labeled an estimate.

## The low-tier reframe (Zak, 2026-11-17 15:14)

Low is a tier, not a handicap. Online, the low tier = small local model
+ free-tier web knowledge (network speed, not weight-bound) + full
system state/metrics. Offline, it answers from stored model knowledge
and system state — narrower, stated, still not useless. The web leg
(websearch.py) is now a registry pipe and a census tier on both boxes;
the PC recognizes 12 pipes, the low VM offers the ask-the-web script
tier from its feeds.

## FLOOR — this VM before any model existed (census run 13:10)

No models, no GPU: the table promised no model at all — script floor +
limited audio, stated plainly. The floor never goes to zero, and it
never lies upward.

## The three comfort options, mapped to measured numbers

1. **Quick** — smallest resident (1.5B class low / 7B door mid): answers
   in ~1s, short-form. 
2. **Balanced — "ok with some delay"** (Zak's test pick): the pinned
   conversation seat (1.5B here at 8.3 tok/s; 14B at mid at 7.7 tok/s,
   zero load wait) + announced on-demand seats for bigger work.
3. **Deep** — batch-class seats (3B on low, 30B on mid): announced
   load, streamed progress, minutes-scale, heartbeat — never silent.

## Lessons already banked

- A VM restart killed the nohup'd lab server: installs need real
  service units (the reference install's persistence doctrine), not
  background shells. The census lab now knows this firsthand.
- The first 3B pull failed silently in a script without set -e and the
  script still wrote READY: a completion marker must be verified
  against the artifact it claims (receipt-anchored), never trusted.
